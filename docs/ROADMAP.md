# 店小力 · 产品更新路线图 v5.1（2026-09-15）

v5 相对 v4 的最大变化：**队列不再按「想到什么做什么」排，而是按「商家有多痛 × 我们做到了多少 × 谁依赖谁」重排。**

## 0. 痛点：对内三类，对外五句

**根因一句话**：小微商户「人即流程」——老板拍板政策、采购报价格、技术答售后、销售管客户；人在就转，人不在就停，人换了知识就丢。店小力卖的不是「省时间」，是把流程从人身上搬进系统。

### 对内认知：三类（决定做什么）

| 类 | 内容 | 失败方式 |
|---|---|---|
| **一、客人等不到答案** | 对外接客：问了没人回，等回过去人已经在别家下单 | 漏单 |
| **二、店里的事实只活在老板脑子里** | 价格、库存、政策没有一个所有人都能问、且答案一致的地方 | **拿不到** / **不一致** / **会过期** |
| **三、钱说不清** | 凭证、对账、到账确认、赊账应收 | 亏钱、扯皮 |

第二类是同一件事的三种失败模式，不是三个问题：只要建起「唯一的事实来源」，三个一起解决。这也决定了交付物要打成一个包（见阶段 B 的 B2），而不是拆成三个小功能分散在不同版本里。

### 对外话术：五句（决定怎么讲）

内部按三类想，对商家讲还是拆成五句——老板听「缺乏单一可信源」没感觉，听下面这五句才点头。而且触发的付费动机不同：第一句是嫌烦，二到五句是怕亏钱，后者更能成交。

| # | 商家自己的话 | 归类 |
|---|---|---|
| 1 | 「上新那天几十个人同时问价，我一个人回不过来。等我回过去，人家已经在别家下单了。」 | 一 |
| 2 | 「销售想给客户报个价，得先来问我。我在开车、在吃饭、在见客户，他就干等着。五个销售问同一个型号，我一天答五遍。」 | 二 · 拿不到 |
| 3 | 「我说一个数，我老婆说一个数，店员说另一个。客人截图拿来对质，我认了就亏钱，不认就得罪人。」 | 二 · 不一致 |
| 4 | 「昨天刚调的价，今天销售还按老价报出去。停产、政策变更、放假安排，全靠我一个一个去说。」 | 二 · 会过期 |
| 5 | 「客人说打了，我说没收到，翻三个月前的聊天记录。集装箱到的那几天，一天一百多张转账截图，手工记账再转清关行，三个小时没了。」 | 三 |

**筛选标准**：这五句必须**跨行业、跨地域都成立**。只对某一类商家致命的（售后重复问答 → 服务型；开票 → 国内；清关行 → 跨境）归到行业包，不占通用底座的优先级。

## 1. 完成度盘点（2026-09-15）

| 类 | 话术 # | 完成度 | 还缺什么 |
|---|---|---|---|
| 一 客人等不到 | 1 | 95% | 模糊问法命中率（产品表加「别名」列） |
| 二 事实只在老板脑子里 · 拿不到 | 2 | **0%** | 员工身份 + 字段可见表 |
| 二 · 不一致 | 3 | 95%（仅买家侧） | 员工侧靠上一行带出，不是独立工作量 |
| 二 · 会过期 | 4 | 30% | 改价后主动推送（**依赖员工身份**）、更新时间外显、知识过期提醒 |
| 三 钱说不清 | 5 | 65% | 凭证按订单归档与回溯 ✅ v1.8.0；到柜期批量与转发未做 |

| 铺量前提（不解决痛点，但决定能否复制） | 完成度 |
|---|---|
| 多租户底座 | **0%** |
| 开通向导小程序 | **0%** |
| 行业包组装 | 30% |
| 企微服务商 / 代开发授权（度小满侧） | 0% |
| 经营画像接口授权与撤回 | 80% |

**结论：痛点侧加权约 75%，铺量前提平均 20%。第一版的关键路径不是再做功能，是多租户 + 开通向导 + 服务商授权。**

B2 必须排在 B1 之后，否则数据模型返工。预计 3–5 天：大脑、商品库、红线、企微通道全现成，员工角色是现有「买家 / 老板」二元身份的第三种，不是新模块；改价推送和更新时间共用同一套身份与字段表，所以打成一个包比拆开便宜。

**v5 → v5.1 的修正**：v5 把「改价推送」放在 A1，理由是「不依赖多租户」。这是错的——它依赖**员工身份**，而系统现在只有买家和老板两种身份，不知道该推给谁。已移入 B2。

## 3. 明确不做

排产 / PDA / 跑图 / 一物一码；抖音 / 小红书 / 视频号自动发布与自动回评（三个平台都没有对第三方开放的发布或私信接口，现有方案全是浏览器模拟 + Cookie，封号风险由商家承担——改为给商家出内容、他自己发，扫码入口统一回企微客服）；备货趋势预测（数据量不足以给出可靠建议）。

已知取舍：进程重启瞬间在飞的老板推送会丢（台账不丢），不做落盘队列。
